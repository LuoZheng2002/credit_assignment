This project proposes a method for obtaining fine-grained credit assignment for agentic LLM fine-tuning through rollout trajectory branching. 

# Idea
## LLM Response Context
We use a lightweight agent framework design:
1. The prompt includes the question and the description of the python tool (the only tool in this project) that the LLM can use. The LLM is supposed to wrap the tool call with `<tool_wait></tool_wait>` tag.
2. The LLM can both reason and use the python tool, and can freely interleave between them.
3. When the framework detects the agent has output the `</tool_wait>` tag, it will pause the generation, inject the tool response, and let the model to continue generation. This happens in the "assistant" section of the context, not as a system or user prompt, as if the tool response is generated by the LLM.
4. The LLM is asked to put the final answer in `\boxed{}`. Once `\boxed{}` is detected when the control is handed to the framework (either eos or `</tool_wait>` is generated), the generation stops and the final answer is submitted. If `eos` is detected but the final answer is not proposed, the framework will inject a prompt asking the model to either continue reasoning or putting the final answer in `\boxed{}`.

## Branching behavior
1. For each question, we generate multiple (4) trajectories end-to-end to start with.
2. Then, we begin to branch on the 4 trajectories.

We can branch from any point in the response, not restricted to the boundary of a step or a sentence. The granularity is at token level.

Assuming that we have determining the branching point, we make the LLM to generate from that point until end, to create the new branch.

For determining a branching point, we can choose one of the following:
1. Choose the middle point of a segment. The trajectory itself is a segment when it does not have a branch. After branching, the trajectory becomes two segments, and so on.
2. Choose an existing branching node, so that after branching, the branching factor of that node is > 2.

The choice of branching point should depend on:
1. The length penalty (for breaking a segment only). If a segment is short with repect to the segment length distribution of the tree, there is more penalty in breaking it.
2. Branching factor penalty (for choosing a node only). The more branching factor on a node there is, the more penalty there is.
3. Segment score or node score.

Segment score calculation:
We use maximum-a-posterioi to model the segment score. The detail is at MAP_PLAN.md, which is a little bit outdated though.

Intuitively, the segment score represents the maximum likelihood of a segment's contribution to the correctness of the final answer divided by the uncertainty. The contribution is signed, where a positive contribution contributes positively and vice versa. The final correctness is modeled as the sign of the sum of all contributions in the trajectory.

We prioritize picking segments with score close to 0 for branching because either the segment has neutral contribution (that will give the most information gain if branching from it and obtaining a binary result), or it has great uncertainty, or both.

The node score is dependent on the segment score. Each node's score is calculated to be (branching factor * parent segment score + sum of (branching factor number of) child segment scores) / (2 * branching factor). It is essentially weighted average of segments incident to the node, with the parent segment to have the same importance as the sum of the child segments.

We also prioritize picking nodes with score close to 0.

The relative segment length penalty and the branching factor penalty ensures that the branching explores all parts of the tree, and avoids concentrating on a specific segment of the tree.

## Advantage calculation
The advantage of each segment of the completed tree is equal to its segment score (contribution likelihood divided by uncertainty), which undergoes a normalization procedure, but does not do shifting.

## Training set generation
For simplicity, we flatten the trees into trajectories with shared early branches. To avoid duplicating the learning for early branches, for each segment, we only allow one training trajectory to learn it. This makes it less worthwhile to train all the trajectories since there are many shared segments not trainable on these trajectories.

To tackle this inefficiency, we adopt a greedy approach to concentrate the training signals on a few branches. For the first trajectory, we find the trajectory with the most per-token-average absolute advantage, and put it in the training set. Then the segments on the trajectories are not allowed to be learned in other trajectories. Then we keep finding the trajectories with largest worth of learning, and put it in the training set. Finally, we aggregate the trajectories among trees and sort them by average absolute advantage, and prune some of the least contributing trajectories.

## Training set ordering
After we have obtained the training samples, we need to find an order of training them.

We order the training samples by their lengths only, hoping that the positive and negative samples can balance in each length interval.

This makes it more efficient for batch training.

Since we have already pruned low average-absolute-advantage samples in training set preparation, we do not need to worry about it here.

## Training interface
For each single sample we provide:
1. input_ids (array of tokenized integers)
2. labels (also array of tokenized integers; should be the same as input_ids for contents to be trained, and -100 for contents not be trained, and should be eos at the first token of tool response) (The eos after tool wait may not be necessary depending on how we end the generation in vllm)
3. attention_mask (for padding induced by batching)
4. advantages (normalized advantage array, the same length as input_ids and labels)

## Ablation on fine-grained credit assignment: compare with GRPO
For each question, do multiple rollouts to obtain group relative advantage.
## Ablation on branch point guidance: compare with TEMPO (natural branching)
Do not use explicit branching guidance but wait for the trajectory to naturally diverge in multiple rollouts.
## Ablation on the maximum-a-posterioi method: compare with TreeRPO
The most prominent characteristic of TreeRPO is that the leaf advantage is either +1.0 or +0.0. It disregards the fact that the leaf node may not be the determining factor for the whole trajectory's accuracy. The modeling is mostly heuristic-based without statistical grounding. We argue that our maximum-a-posterioi method is better at estimating each segment's real contribution.

## Optional: Ablation on TreePO
The advantage in TreePO is determined by group relative among segments that share the same prefix.

# Innovation and Openreview insights
## Compare with TEMPO
Our method solves reviewer's concern about the "limited branch overlap" by explicitly guide the branching point.

## Compare with TreeRPO
The reviewers say that the training is inefficient because of high sampling cost. We do not have this problem because every segment in the tree has its advantage label and can be trained on. Although in practice we do not train on all of them due to the inefficiency of the flattening method, it is theoretically possible to utilize all segments efficiently by reusing the gradients before the branching point.

Reviewers asked for comparisons against PRM-based and step-level methods (e.g., Math-Shepherd, Step-DPO), not only GRPO. I guess we also will not do PRM-based method due to workload. For step-level methods, our approach can work on token-level, so it's more flexible.

## Compare with TreeOPO
This paper uses a stronger teacher model to generate reference trajectories, while ours do not rely on stronger model or referece trajectory.

## Compare with TreePO
TreePO computes the advantage of a segment by comparing it with other segments at the same subgroup level. This is less flexible than our method, and does not explore parent-child advantage relationship.
